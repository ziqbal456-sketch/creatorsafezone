## Each Guide Batch

1. Inventory existing live and prepared URLs, including their bodies and release dates. Read the current register and source identity module.
2. Give each distinct reader job one intent owner. Group synonym queries under that owner; preserve published URLs and IDs.
3. Record primary evidence for entity relationships and factual attributes. Separate proposed queries, search observations, user-confirmed facts, documented facts and unknowns.
4. Add the new guide's ownership row, topic keys, author/publisher/site references and exact release date. Preserve existing identity records and provenance.
5. Check names, stable IDs, visible bylines, profile links, canonical URLs, schema headlines and dates. Tests render every prepared guide with a local future clock; public access stays date-gated.
6. Run structural validation, the identity/discovery/publication tests, editorial audit and responsive review. Check live identities and newly due URLs after release. Update the source/version/rollback record and register status from actual evidence.

No topic coverage score, KGR result or schema vocabulary establishes indexing, ranking, expertise or a Knowledge Panel. Keep unknown metrics unknown. A source timestamp records the review actually performed, not a new platform measurement.
